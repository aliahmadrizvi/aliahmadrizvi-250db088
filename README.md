# Aliahmadrizvi

PROJECT: Ali Ahmad Rizvi — Premium Motion-Driven Developer Portfolio

1. Project objective

Build a premium, immersive, responsive personal developer portfolio for Ali Ahmad Rizvi, a B.Tech Computer Science and Engineering student at Integral University, Lucknow, India.

The website should feel like a custom-designed digital experience, not a generic portfolio template.

Use these websites as creative references:

- Reference 1: https://sarthak-sharma-portfolio-six.vercel.app/
  Study its editorial layout, typography, motion-led storytelling, scrolling text, and transitions. Reinterpret these principles in an original design.

- Reference 2: Olivia Rodrigo's visual aesthetic and creative direction.
  Take inspiration from expressive typography, dreamy purple lighting, film grain, scrapbook-like textures, expressive imagery, and playful transitions. Do not copy copyrighted website layouts, photographs, logos, or assets.

The final result should combine a sophisticated developer portfolio with expressive editorial art direction.

2. Technology stack

Use:

- React
- TypeScript
- Vite
- Tailwind CSS
- Framer Motion or Motion for React
- Lucide React icons

Use reusable components, a clean folder structure, and maintainable code.

Do not introduce a backend unless a specific feature requires it.

3. Visual design system

Theme: Dark, cinematic, editorial, modern, expressive.

Colors:

- Background: near-black #09090F
- Secondary background: #11111A
- Primary accent: lavender #B69AFF
- Secondary accent: mint #7CF7C4
- Main text: #F4F2FB
- Muted text: #9896A8

Typography:

- Use a bold, expressive sans-serif for headlines.
- Use a highly readable sans-serif for body text.
- Use a monospace font for labels, project numbers, and technical details.

Design rules:

- Use oversized typography and generous spacing.
- Mix asymmetrical layouts with a clear visual hierarchy.
- Use subtle borders, restrained glow effects, layered backgrounds, and occasional grain texture.
- Avoid excessive glassmorphism, excessive gradients, and generic dashboard-style cards.
- Make every section feel art-directed.
- Use a consistent spacing system, responsive typography, and reusable design tokens.

4. Website structure

Build these sections in this order:

1. Sticky navigation
2. Hero section
3. Scrolling technology marquee
4. About me
5. Skills and technology stack
6. Selected projects
7. Education
8. Certificates and learning
9. Achievements and milestones
10. Contact section
11. Footer

Navigation must smoothly scroll to the correct section and clearly indicate the active section.

6. About me

Explain that I am developing my programming fundamentals and exploring software development, web design, data analysis, and AI.

Use honest, student-appropriate wording. Do not invent professional employment, client work, awards, or experience.

Create an editorial layout with a strong heading, readable text, and three small highlights:

- Computer Science
- Development and Data/AI
- Learning by Building

- Add project numbers, technology tags, descriptions, and hover effects.

- Include GitHub and Live Demo buttons only when valid URLs are provided.
- If a URL is unknown, show a clear placeholder in the data model or omit the link.
- Do not invent project statistics, users, downloads, or performance metrics.

Keep certificate URLs optional. Do not invent certificate IDs, verification links, or completion claims.

11. Achievements and milestones

Present factual learning milestones:

- Building web development projects
- Practising DSA with C++

Do not fabricate awards, rankings, hackathon wins, or professional achievements.

12. Contact

Create a strong, visually distinctive contact section with:

- An invitation to collaborate
- Email button
- GitHub link
- LinkedIn link

Use placeholders for unknown email and LinkedIn URLs. Make these values easy to update in one configuration file.

The contact buttons must not lead to fake URLs. Do not create a fake working contact form.

13. Responsive behavior

Design mobile-first and test:

- Small Android phones
- Large phones
- Tablets
- Laptops
- Large desktop screens

The mobile menu must work correctly. Avoid horizontal overflow, oversized fixed elements, and animations that interfere with reading.

14. Accessibility and performance

- Use semantic HTML and keyboard-accessible controls.
- Add visible focus indicators.
- Respect prefers-reduced-motion.
- Ensure readable contrast.
- Lazy-load nonessential images.
- Avoid unnecessary dependencies and expensive continuous animation.
- Keep animations smooth on mid-range mobile devices.

15. Architecture

Use reusable components for:

- Navbar
- Hero
- Marquee
- Section headings
- Skills
- Project cards
- Education
- Certificates
- Achievements
- Contact
- Footer

Keep project, skills, certificate, and social-link content in separate data/configuration files where appropriate.

16. Phase 1 completion criteria

For this phase:

- Create the complete responsive site structure.
- Implement the design system.
- Build all sections with realistic content.
- Add working navigation and basic hover states.
- Use tasteful entrance transitions only.
- Keep the structure ready for more advanced animations in Phase 2.
- Ensure the application runs without errors.

Do not attempt every complex animation yet. Prioritise a cohesive visual foundation, good responsive behavior, and clean code.

At the end, summarise what was implemented, list any placeholders, and identify the exact next steps for Phase 2. Preserve all working functionality when future phases are added.
